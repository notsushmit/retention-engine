# Scoring API

Generated by `python -m retention.api write-docs` from configs/serving.yaml and the response schemas. Do not edit by hand; tests/test_scoring_docs.py checks that this file equals a fresh build.

> The service replays 2016 KKBox data; there is no live source.
> Customers expiring more than 30 days ahead (22% of active customers on 2016-11-01) get no score.
> Plans exist for two dates only (2016-10-01 and 2016-11-01) and were built from the 30-day probability before the ordering fix.
> KKBox backtest figures are model estimates under assumed effects, not observed outcomes.

## Endpoints

### GET /health

Fields: `ready`, `store_date`, `replay_progress`, `model_checksums_match`, `config_sha256`, `valkey_reachable`, and `reason` (not registered; see below). It answers 503 with the reason when the service is not ready.

### POST /score

Request: `msno` (required) and `as_of` (optional). Features come from the service's own store; callers never post feature values.

Answers: `scored`, `outside_population` (codes `segment_trial_only`, `segment_promo_only`, `expiry_beyond_30_days`, `unseen_level:<feature>`, and `unseen_level:hidden_feature` under amendment A5) or `not_active`.

Errors:

- 404: unknown customer
- 422: malformed input
- 409: as_of differs from the store's date
- 503: not ready; a model checksum mismatch stops startup and /health says why

### GET /at-risk

Parameters: `horizon` (one of 7, 30, 59; default 30), `limit` (default 50, at most 1000), `offset`, and the filters `auto_renew`, `in_plan`. Anything else is a 422.

Order: final probability at the horizon, descending; ties by msno. Plan cell: strategy optimizer, scenario base, budget 5,000.

Every plan field reads "plan built from the 30-day probability before the ordering fix". Header note: "Ranking uses the final probability; plan membership comes from the Phase 7 plan." A date without a plan reads "no plan for this date".

### GET /alerts

Kinds: trend, event. A trend alert is shown when the registered rule holds: week start + 37 days on or before the store's date. Every trend alert carries the labels "exploratory", "false-alarm rate not validated", "detected in hindsight on the series through 2016-12-19", and its stored data-quality flags. The dimensions registered in api.alerts.trend.hidden_dimensions are removed from top_segments, too_small_segments (amendment A7) and dimension_totals, and the number removed is shown. Each cancel event reads "a cancel row, not a change in risk".

## Amendments A5 to A8

- A5 (2026-10-21, amends contract.outside_population.codes): an unseen level in a feature whose name contains a never-used attribute as a whole word (the response scan's own test) reads `unseen_level:hidden_feature`; for any other feature the code names the feature, `unseen_level:<feature>`.
- A6 (2026-10-21, amends contract.never_in_any_body, step5.scan): only the value of the msno field of a /score body and the row ID (msno) of each /at-risk row, and only when that value equals the requested customer's own ID or the listed customer's own ID; every other field and key of every response, the same string in any other field, another customer's ID in the msno field, and every error body are scanned in full. An identifier exemption, not a relaxation of the never-used rule. 3 of 425,520 known IDs contain one never-used word as a whole word; 5 of 1,474,743 distinct IDs across the seven tables do (distinct IDs, not table rows).
- A7 (2026-10-21, amends api.alerts.trend.hidden_dimensions): the hidden dimensions are also removed from too_small_segments, and every segment removed there is counted in the number hidden shown on the alert. Whole-word hits before hiding, summed over the trend alerts: top_segments 4, dimension_totals 10, too_small_segments 65, every other field 0. The pinned file is unchanged.
- A8 (2026-10-21, amends step5.alerts.trend_knowable_at_2016_11_01): the registered value 7 was wrong; under the unchanged rule (week start + 37 days on or before the store's date) the pinned file gives 6 at 2016-11-01; cp7 (week 2016-09-26) is knowable from 2016-11-02.

## Notes

- The group that the registered statement above says is never shown as a reason is listed as a reason in 11,368 rows of Phase 4's reasons.parquet (2016-10-01 and 2016-11-01); that file, Phase 4's docs and its phrases file are left as they are (amendment A3).
- The three derived strings are the December 2016 withheld code "2016-12 not explained", the warning "data warning about the 2016-12-05 missing-renewal day" and the status "scored"; they are taken by fixed patterns from the contract's descriptions in src/retention/api/labels.py, not registered verbatim.
- POST /score scores each customer together with a placeholder copy of the row and returns only the customer's own answer. This is a workaround that relies on NumPy's summation behaviour, chosen after the exact-equality test failed, not a fix of its source: Phase 7's expected-days sum adds a one-row array in another order than an array of several rows (D-199).
- The test that recomputes the knowable count from the pinned alerts file skips in CI, because the pinned file is not in git; it runs where the file exists and checks amendment A8's count.

## Choices not registered

- /health carries a reason field beside the registered fields.
- msno must be a non-empty string; as_of must be written YYYY-MM-DD.
- A 422 body never returns the validation details, so no field name a caller sent comes back.
- Unknown paths and methods keep the framework's "Not Found" and "Method Not Allowed" bodies.
- Every /health, /score, /at-risk and /alerts call hashes the downloaded model files and both pinned files again.
- Startup refuses loaded model files that differ from the bundle the response schemas register.
- The /at-risk auto_renew filter takes on or off; in_plan takes true or false.
- An in_plan filter on a date without a plan is a 422.
- Each /at-risk row shows the customer's auto_renew.
- The /at-risk header counts list only the stored outside-population codes.
- /alerts takes no parameters.
- Cancel events are read as objects with msno and date; the replay must write that form.
